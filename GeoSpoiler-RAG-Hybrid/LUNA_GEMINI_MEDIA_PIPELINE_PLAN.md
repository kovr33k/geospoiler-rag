# План внедрения гибридного медиаконтура Luna Vision + Gemini Audio

Дата плана: 2026-08-11
Статус документа: historical implementation plan; не использовать как current acceptance report.
Цель: перевести распознавание визуальной части изображений и видео на локальную `gpt-5.6-luna`, оставить распознавание звука на Gemini и передавать объединённый результат в существующее Luna-обогащение Enriched v2.

## Текущий статус — 2026-08-12

Контрактные исправления этого плана реализованы и проверяются по `POST_PUSH_REVIEW_CLOSEOUT_TZ_FINAL.md`. Текущий canonical manifest содержит четыре источника и принят `4/4`; актуальные machine-readable доказательства находятся в `artifacts/accepted_manifest_load_report.json` и closeout artifacts. Исторические формулировки ниже сохраняются только как журнал решений.

## 1. Зафиксированное решение

Распределение ответственности должно быть однозначным:

| Данные | Основной обработчик | Резерв | Назначение |
|---|---|---|---|
| Текст Telegram/Instagram | Luna | запрещён скрытый API fallback | Нормализация и смысловое обогащение |
| Изображения и карусели | Luna | только явно включаемый прежний vision-контур | OCR и описание визуального содержания |
| Видеокадры | Luna | только явно включаемый прежний vision-контур | OCR, объекты, действия и контекст сцены |
| Аудио, голос и звуковая дорожка видео | Gemini | `openai/whisper-large-v3` | Дословная транскрипция речи |
| Финальная Enriched v2 карточка | Luna | запрещён скрытый API fallback | Объединение caption, OCR, визуального описания и транскрипции |

Целевой поток:

```text
caption/text ----------------------------------------------+
                                                            |
image ----------------> Luna visual/OCR --------------------+--> normalized
                                                            |    canonical sections
video --> ffmpeg frames --> Luna visual/OCR ----------------+         |
      \-> ffmpeg audio --> Gemini --> Whisper fallback -----+         v
                                                               Luna Enriched v2
```

Luna не получает аудиофайлы и не считается STT-моделью. Gemini не участвует в финальном смысловом обогащении. Код, а не LLM, отвечает за статусы, provenance, cache identity и pipeline-owned quality flags.

## 2. Почему нужна именно гибридная схема

- Практический тест подтвердил, что локальная Luna умеет анализировать изображения и извлечённые видеокадры через read-only Codex CLI.
- Практический тест не подтвердил способность локальной Luna слышать или транскрибировать MP3/MP4.
- В пяти контрольных материалах Luna лучше восстановила визуальное содержание `Китай/6`, `Китай/72` и `Ультра/16`.
- В `Балтийские страны/4` и `Ультра/18` аудиотранскрипция прежнего Gemini-контура содержала важные детали, которых нельзя получить только из кадров.
- Следовательно, замена Gemini на Luna во всём медиаконтуре приведёт к потере звуковой части. Объединение Luna Vision и Gemini Audio сохраняет оба типа доказательств.

## 3. Границы работы

Входит в работу:

- нативные изображения и видео Telegram;
- Instagram Reel и carousel;
- общий визуальный backend Luna;
- существующий Gemini/Whisper audio-контур;
- детерминированное объединение результатов в normalized;
- точечная перегенерация затронутых Enriched-карточек;
- проверка FTS, source registry и Late-Fusion после принятия результата.

Не входит в работу:

- изменение embedding-модели;
- включение reranker;
- включение Wiki;
- полный ре-энричмент до успешного пилота;
- автоматическое принятие сомнительных результатов через UI;
- скрытый переход с Luna на Gemini Vision при ошибке.

## 4. Разрешённые существующие интерфейсы

- `llm_backend.complete_text_sync(...)` остаётся текстовым Luna-интерфейсом.
- `_build_codex_command(...)` и `_run_codex(...)` используются для общего запуска Codex CLI.
- `normalizer/instagram/frames.py` уже содержит извлечение, дедупликацию и фильтрацию видеокадров.
- `normalizer/transcription_handler.py` уже владеет Gemini-транскрипцией и Whisper fallback.
- `normalizer/instagram/builder.py` задаёт канонические секции:
  - `[Транскрипция аудио]`;
  - `[Текст с экрана (OCR)]`;
  - `[Описание ролика]`.
- `normalizer/pipeline.py` собирает media-секции normalized-документа.
- `python main.py validate enriched --fail-on-error`, `python main.py fts rebuild` и `python main.py registry rebuild` остаются штатными проверками и операциями.

Нельзя предполагать наличие недокументированного флага Codex CLI `--image`. Проверенный способ — временно разместить изображения в изолированном runtime-каталоге и разрешить Luna прочитать их по относительным путям в sandbox `read-only`.

## 5. Фаза 0 — неизменяемый preflight

### Работа

1. Зафиксировать ветку, commit и чистоту worktree.
2. Снять без секретов активные значения:
   - `LLM_PROFILE`;
   - `CODEX_LUNA_MODEL`;
   - `CODEX_LUNA_REASONING_EFFORT`;
   - `CODEX_FALLBACK_TO_API`;
   - `VISION_MODEL`;
   - `TRANSCRIPTION_MODEL`;
   - `TRANSCRIPTION_STT_MODEL`;
   - Instagram deep-extract settings.
3. Создать manifest пяти контрольных источников и их media-файлов с SHA-256.
4. Зафиксировать текущие normalized и Enriched версии как baseline.
5. Выполнить по одному изолированному smoke:
   - Luna читает тестовое изображение;
   - Gemini транскрибирует короткий аудиофрагмент;
   - Whisper вызывается после контролируемой ошибки Gemini.
6. Выполнить `yt-dlp` preflight именно через Python проекта:
   - получить установленную версию через `sys.executable -m yt_dlp --version`;
   - проверить её относительно минимальной версии из зависимостей проекта;
   - запросить последний stable release из официального GitHub API;
   - сохранить installed/latest version и время проверки в run-manifest;
   - выполнить extractor-smoke на одном публичном Reel без загрузки полного файла.

На дату составления плана локальная версия `2026.07.04` совпадает с последним официальным stable release `2026.07.04`. Проверка должна выполняться заново перед каждым live media-backfill, потому что Instagram меняет выдачу независимо от кода проекта.

### Gate

- Никакие production normalized, enriched, state и индексы не изменены.
- Luna identity равна ожидаемой `codex-cli:gpt-5.6-luna@xhigh`.
- Gemini и Whisper доступны через текущий OpenRouter-контур.
- Пять исходных media-файлов доступны и однозначно привязаны к карточкам.
- Установленный `yt-dlp` не ниже project minimum, совпадает с актуальным stable release и проходит extractor-smoke.

## 6. Фаза 1 — конфигурация и контракт результата

### Работа

Добавить явную маршрутизацию, например:

```text
MEDIA_VISION_BACKEND=luna
MEDIA_VISION_TIMEOUT_SECONDS=<ограниченное значение>
MEDIA_VISION_MAX_FRAMES=<ограниченное значение>
MEDIA_VISION_PROMPT_VERSION=<версия>
MEDIA_VISION_FALLBACK_ENABLED=false
```

Сохранить без изменения ответственности:

```text
TRANSCRIPTION_MODEL=google/gemini-2.5-flash-lite
TRANSCRIPTION_STT_MODEL=openai/whisper-large-v3
```

Ввести единый программный результат визуального анализа:

```text
VisualExtractionResult
  status: success | unavailable | failed
  text: str
  model: str
  artifact_path: str | null
  error: str | null
  frame_count: int
  input_sha256: str
  prompt_version: str
```

В media-метаданных normalized хранить `visual_status`, `visual_model`, `visual_artifact_path`, `visual_error` и число обработанных кадров. Секреты и полный prompt в карточку не записывать.

`transcript_unavailable` остаётся pipeline-owned quality flag. Новый `visual_unavailable` в Enriched v2 пока не добавляется: визуальный статус хранится в media-метаданных. Если отсутствуют и звук, и визуальный результат, pipeline создаёт явную review-причину и применяет уже существующие правила `no_substantive_content`/`extraction_unstable`, а не просит LLM придумать флаг.

### Gate

- Старые конфигурации читаются без ошибки.
- Backend и fallback нельзя включить неявно.
- Модель и backend каждого результата доказуемы из метаданных.
- LLM не может назначать или удалять pipeline-owned статусы.

## 7. Фаза 2 — отдельный Luna Visual backend

### Работа

1. Добавить отдельный публичный интерфейс анализа изображений, не меняя семантику `complete_text_sync(...)`.
2. Для каждого вызова:
   - создать изолированный временный runtime-каталог;
   - скопировать только разрешённые image-файлы под детерминированными именами;
   - проверить расширение, MIME, размер и количество файлов;
   - передать Luna относительные пути и строгую русскоязычную инструкцию;
   - запустить Codex CLI в `read-only`;
   - сохранить финальный ответ и очистить временные файлы.
3. В prompt потребовать:
   - дословный OCR отдельно от описания;
   - только видимые факты;
   - явное обозначение неуверенности;
   - запрет на внешние знания и уверенную идентификацию лиц без визуального основания;
   - сохранение значимых надписей на исходном языке и русское описание контекста.
4. Ограничить timeout, число параллельных процессов, число кадров и суммарный объём входа.

### Anti-pattern guards

- Не передавать аудио в Luna.
- Не кодировать изображение как огромный base64-текстовый prompt.
- Не ослаблять действующее правило текстового backend, запрещающее инструменты.
- Не открывать Luna доступ на запись в проект.
- Не использовать общий временный каталог между конкурентными задачами.

### Gate

- Unit-тесты доказывают staging, очистку, timeout и корректное возвращение статуса.
- Ошибка одного файла не превращается в пустой `success`.
- Отсутствует скрытый HTTP/Gemini fallback.
- Опциональный live-smoke распознаёт заранее известный текст на изображении.

## 8. Фаза 3 — общий модуль визуальной обработки media

### Работа

1. Вынести или безопасно переиспользовать извлечение кадров так, чтобы нативное Telegram-видео не зависело от внутренних функций Instagram pipeline.
2. Реализовать единые операции:
   - `analyze_image(...)`;
   - `analyze_video_frames(...)`;
   - выбор кадров по времени;
   - дедупликация похожих кадров;
   - отбрасывание пустых/неинформативных кадров;
   - небольшие Luna-батчи, чтобы не повторить прежние длинные timeout.
3. Сохранять отдельный JSON-артефакт визуального анализа с:
   - SHA-256 входа;
   - backend/model identity;
   - prompt version;
   - настройками кадров;
   - timestamp каждого кадра;
   - OCR, описанием, статусом и ошибкой.
4. Cache key строить из SHA-256 media, backend, модели, prompt version и параметров кадров.

### Gate

- Повторный запуск с той же identity использует cache.
- Смена backend, модели, prompt или frame settings инвалидирует cache.
- Старый Gemini OCR не может выдаваться за новый Luna-результат.
- Артефакт позволяет вручную понять, какие кадры увидела модель.

## 9. Фаза 4 — интеграция всех media-маршрутов

### 9.1 Нативные изображения Telegram

- Перевести `normalizer/image_handler.py` на общий visual router.
- При `MEDIA_VISION_BACKEND=luna` вызывать Luna Visual.
- Прежний HTTP Vision оставить только как явно выбранный backend или явно разрешённый fallback.

### 9.2 Нативные видео Telegram

- В `normalizer/pipeline.py` независимо запускать:
  - извлечение аудио и Gemini/Whisper transcription;
  - извлечение кадров и Luna visual/OCR.
- Объединять результаты только после завершения обеих ветвей.

### 9.3 Instagram Reel

- Перед первым deep-extract в процессе выполнить один `yt-dlp` runtime-check; не повторять сетевой запрос для каждого Reel.
- Сохранить текущую загрузку публичного Reel и аудиотранскрипцию.
- Перевести OCR/описание кадров на общий Luna Visual backend.
- Итоговое описание ролика формировать Luna из caption, транскрипции и визуального результата.
- Обновить Instagram cache version и signature.

Политика версий `yt-dlp`:

- версия ниже project minimum — hard failure до скачивания media;
- версия ниже актуального stable release — hard failure для управляемого backfill и понятная инструкция обновления локального `.venv`;
- недоступен GitHub API — live-backfill не стартует в строгом режиме, обычная нормализация может продолжиться без deep extraction с явным статусом;
- pipeline никогда не запускает `pip install`, `yt-dlp -U` или иное самообновление автоматически;
- после ручного обновления обязательны повторный version-check и extractor-smoke.

### 9.4 Instagram carousel

- Перевести каждое изображение карусели на общий Luna Visual backend.
- Сохранить порядок слайдов и не смешивать OCR разных изображений без номера слайда.

### Правило объединения

Использовать только существующие канонические секции normalized:

```text
[Транскрипция аудио]
...

[Текст с экрана (OCR)]
...

[Описание ролика]
...
```

Не вводить произвольную секцию вроде `[Luna visual media extraction]`: тест показал, что semantic enricher может её проигнорировать.

Аудио и визуальная ветвь имеют независимый partial success. Ошибка аудио не удаляет OCR; ошибка визуального анализа не удаляет транскрипцию. Caption-only результат при включённом deep extraction должен сопровождаться явным статусом и review-причиной, а не считаться незаметным полным успехом.

### Gate

- Все четыре маршрута используют одного владельца визуальной логики.
- Все аудиомаршруты по-прежнему принадлежат Gemini/Whisper.
- В логах и метаданных видны отдельные статусы обеих ветвей.
- Existing canonical sections потребляются Enriched pipeline без специального исключения.

## 10. Фаза 5 — автоматические проверки

### Unit-тесты

- Luna Visual получает только изображения и относительные пути.
- Аудиофайл отвергается visual backend до запуска CLI.
- Timeout/invalid output возвращает `failed`, а не пустой `success`.
- Gemini остаётся первым audio backend.
- После контролируемого Gemini 400 вызывается Whisper fallback.
- Смена visual identity инвалидирует cache.
- Instagram Reel и Telegram video сохраняют одновременно audio и visual результаты.
- Carousel сохраняет порядок слайдов.
- Используются точные канонические заголовки секций.
- LLM не может самостоятельно выставить pipeline-owned flags.
- Тесты не меняют production state, normalized, enriched и индексы.

### Integration-тесты

- Искусственное видео с известной надписью и речью даёт обе секции.
- Visual failure + успешное audio даёт валидный partial result.
- Audio failure + успешное visual даёт валидный partial result.
- Обе ошибки создают review-required запись и не маскируются как полная карточка.
- Публичный Instagram URL проходит актуальный downloader flow без cookies, если сам источник доступен.
- `yt-dlp` preflight различает outdated, offline и extractor-broken состояния и не сообщает ложный `success`.
- Устаревший локальный media path корректно переопределяется найденным актуальным файлом только внутри разрешённых media-каталогов.

### Общий Gate

- Targeted tests зелёные.
- Полный pytest зелёный при `LATE_FUSION_ENABLED=false` и `true`.
- Ruff и `git diff --check` зелёные.
- Реальные production state и output не изменены тестами.

## 11. Фаза 6 — изолированный live-пилот на пяти материалах

Контрольный набор:

1. `Китай/6`;
2. `Китай/72`;
3. `Балтийские страны/4`;
4. `Ультра левые и ультра правые/16`;
5. `Ультра левые и ультра правые/18`.

### Порядок

1. Запустить новый hybrid pipeline в отдельный run-каталог, не перезаписывая production.
2. Сохранить для каждого источника:
   - исходный caption;
   - Luna OCR/visual artifact;
   - Gemini/Whisper transcript artifact;
   - объединённый normalized;
   - Luna Enriched v2;
   - latency каждой стадии;
   - backend/model/fallback identity.
3. Сравнить с текущим Gemini+Luna baseline вручную по пяти ранее использованным критериям:
   - полнота фактов;
   - точность и отсутствие выдумок;
   - полезность визуального контекста;
   - качество структуры/сводки;
   - поисковая пригодность.
4. Отдельно сравнить latency, ошибки, fallback и provenance.

### Критерии принятия пилота

- 5/5 карточек проходят структурную и semantic validation.
- Luna visual успешно обрабатывает доступные изображения/кадры всех пяти источников.
- Для материалов с речью присутствует Gemini-транскрипция либо доказуемый Whisper fallback/явный unavailable status.
- `Балтийские страны/4` и `Ультра/18` не теряют существенные аудиодетали baseline.
- `Китай/6`, `Китай/72` и `Ультра/16` сохраняют подтверждённое преимущество визуального анализа Luna.
- Ни один источник не превращается молча в caption-only.
- Все URLs/provenance валидны.
- Luna ни разу не вызывается с аудиофайлом.

Если хотя бы один содержательный материал стал хуже из-за новой маршрутизации, production activation не выполняется: исправляется конкретная стадия и весь пилот повторяется на неизменном наборе.

## 12. Фаза 7 — ограниченный backfill и повторное ревью

После принятия пилота:

1. Создать резервную копию затрагиваемых normalized, enriched, progress и индексов.
2. Построить manifest только media-источников с отсутствующей или устаревшей visual identity.
3. Сначала обработать один небольшой канал/пакет.
4. Выполнить автоматическую проверку и ручную выборку:
   - длинное видео;
   - короткий Reel;
   - carousel;
   - изображение с большим количеством текста;
   - видео без речи;
   - аудио без значимых кадров;
   - недоступный media-файл.
5. Проверить долю `success`, `partial`, `failed`, среднюю/p95 latency и число fallback.
6. После принятия карточек выполнить точечную синхронизацию их нового `graph_text` в LightRAG по manifest затронутых `source_id`.
7. Проверить, что каждый старый LightRAG-документ заменён по стабильному source path, а не продублирован новым content-based ID.

### Gate

- Нет систематической потери аудио или OCR.
- Нет массового роста `no_substantive_content`, `transcript_unavailable` или review queue.
- Все результаты имеют корректную model identity.
- Повторный запуск идемпотентен и использует cache.
- Обновлённые карточки находятся через LightRAG и Late-Fusion; старые версии их текста больше не возвращаются.

## 13. Фаза 8 — управляемая синхронизация с RAG

Сейчас `python main.py load` безопасно заменяет существующие LightRAG-документы по стабильному source path, но перебирает весь Enriched-корпус. Для медиапилота и последующего частичного backfill нужно добавить ограниченный режим загрузки, например:

```powershell
python main.py load --manifest artifacts/<run_id>/accepted_sources.json
```

### Контракт manifest

- список точных `source_id` и `provenance.normalized_path`;
- SHA-256 принятой Enriched-карточки и её `graph_text`;
- run identity нового media-контура;
- запрет путей вне штатных normalized/enriched-каталогов;
- ошибка при отсутствующем, дублирующемся или несовпадающем source.

### Порядок

1. До загрузки снять backup активного `rag_storage/` или убедиться в наличии актуального проверенного backup.
2. Загрузить только карточки из accepted manifest через существующий `_upsert_text(...)`.
3. Для каждого source доказать:
   - старый doc найден по стабильному path-derived ID;
   - старый doc удалён успешно;
   - новый `graph_text` вставлен и дошёл до terminal success;
   - source metadata index обновлён.
4. Запустить контрольные запросы, которые должны находить новые аудио- и визуальные факты.
5. Проверить отсутствие старого текста и дублей документа.

Полный `python main.py rebuild` для обычной дозагрузки не используется. Он остаётся только процедурой полного пересоздания графа из актуального корпуса при отдельном решении и с уже существующим backup/rollback.

### Gate

- Все source из manifest успешно обновлены; skipped/failed равно нулю.
- Количество логических документов не увеличилось из-за повторной загрузки тех же source.
- Новые факты видны в LightRAG и в объединённом Late-Fusion ответе.
- Ошибка одного source останавливает публикацию run-а и сохраняет отчёт для rollback.

## 14. Фаза 9 — полный rollout

1. Остановить процессы записи в normalized/enriched/indexes.
2. Создать проверенный backup и SHA-256 manifest.
3. Выполнить backfill visual evidence для оставшихся media-источников.
4. Перегенерировать только затронутые Enriched-карточки Luna, а не весь корпус без причины.
5. Загрузить принятые обновлённые карточки в LightRAG по точному accepted manifest.
6. Запустить:
   - `python main.py validate enriched --fail-on-error`;
   - пересборку Card FTS;
   - пересборку source registry;
   - Late-Fusion smoke с `LATE_FUSION_ENABLED=true`;
   - проверку citations и source URLs.
7. Сверить до/после:
   - число карточек;
   - множество `source_id`;
   - распределение model identity;
   - число media success/partial/failed;
   - число review-required;
   - retrieval smoke results.
8. Только после всех gate включить `MEDIA_VISION_BACKEND=luna` как постоянную production-настройку.

## 15. Rollback

Rollback выполняется при потере карточек, систематическом ухудшении качества, некорректной model identity, повреждении индексов или недопустимом росте ошибок.

Порядок:

1. Остановить процессы записи.
2. Вернуть предыдущую настройку visual backend.
3. Восстановить normalized/enriched/state/indexes из проверенного backup.
4. Сверить SHA-256 и counts.
5. Выполнить validation и retrieval smoke уже на восстановленном состоянии.

Артефакты не удалять до полного закрытия инцидента: они нужны для сравнения и причины отката.

- Luna обрабатывает визуальную часть нативных Telegram image/video и Instagram Reel/carousel.
- Gemini является первым обработчиком любого аудио; Whisper — контролируемым fallback.
- Зафиксировано ноль попыток передать аудио в Luna.
- Caption, OCR/visual и transcript объединяются до Luna Enriched v2.
- Используются канонические normalized-секции, которые реально потребляет enricher.
- Ни одна ошибка media не маскируется как полный успех.
- Backend/model/prompt/cache identity сохранены и проверяемы.
- Cache инвалидируется при любой смене значимой identity.
- `yt-dlp` проверяется относительно project minimum и текущего stable release перед live-backfill; extractor-smoke обязателен.
- Пять контрольных карточек приняты по содержанию и не имеют регрессий.
- Все принятые обновлённые карточки точечно синхронизированы с LightRAG без дублей и stale-текста.
- Targeted и полный набор тестов проходят в обоих профилях Late-Fusion.
- Enriched validation, FTS, registry, Late-Fusion smoke, citations и URLs проходят.
- Есть проверенный backup и отработанный rollback.
- Git worktree после реализации понятен, изменения оформлены отдельными осмысленными commit-ами.
