# GeoSpoiler RAG: оценка модулей и поиск готовых решений

Дата исследования: **26 октября 2026 года**. Исходная ревизия: `5ba0754`, ветка `codex/project-structure`, с существующими локальными изменениями.
Это исследование кода, документации и реестров пакетов. Установка кандидатов, прогоны моделей и проверка прироста качества не выполнялись.

## Основной вывод

У проекта уже содержательная архитектура для личной OSINT-памяти: архив normalized, контракт Enriched v2, сохранённое происхождение, SQLite FTS, отдельный графовый канал, Late Fusion и проверка ссылок.
Самые полезные находки — небольшие инструменты возле существующих модулей: **Lingua для пропуска лишнего перевода, Trafilatura для статей и ir-measures для измерения поиска**.
Docling и локальная транскрипция интересны при соответствующих материалах. Новая vector DB, другой RAG-фреймворк и автоматическая графовая память пока не имеют доказанного преимущества.
Сначала стоит реализовать уже согласованный ingestion-план: он устраняет видимые лишние вызовы и повторную работу без смены модели или содержания ответов.

## Область и ограничения

- Сохраняются текущие `luna`, `gpt-6-luna`, `xhigh`, правила контекста и выбранное содержание источников.
- Обычный `run` и явный `load` остаются разными операциями; Wiki остаётся выключенной.
- Нельзя представлять сокращение числа токенов как улучшение качества или молча выбрасывать содержание постов и видео.
- Новый LLM-валидатор каждого ответа, расширенная кампания оценки цитирования и новые замеры без диагностической необходимости не согласованы.
- Публикация спецификации и зелёные исторические тесты не означают реализации ingestion-плана или проверки нынешнего live-ответа.
- На хосте Python 3.14; пакет проекта объявляет поддержку `>=3.11`. Это разные требования совместимости.
- На снимке файлов: 129 normalized-текстов, 131 enriched-карточка, 22 JSON в enriched_segments. Это подсчёт файлов, не число уникальных источников или валидных поколений.

Основания: [архитектура](../../ARCHITECTURE.md), [контракты](../../DATA_CONTRACTS.md), [согласованные решения](../specs/INGESTION_SPEED_DECISIONS_20261025.md), [спецификация](../specs/RAG_INGESTION_AND_GITHUB_SPEC_20261025.md), [зависимости](../../pyproject.toml).

## Каналы поиска

Проверены локальные исходники и README модулей, публичные GitHub-репозитории владельцев, официальная документация, JSON API PyPI и npm для выбранных кандидатов.
MCP рассмотрен через официальный Docling MCP и доступный каталог инструментов. Наличие сервера в интернете не означает, что он подключён или протестирован здесь.
Локальный каталог skills доступен; используются `search-first`, `research`, Context7. Дополнительные skills и плагины не устанавливались.
Context7-проверки LightRAG, Docling и Ragas дополняют исследование основного агента. Это выборочный поиск подходящих решений, не исчерпывающий обзор всех пакетов PyPI/npm/MCP.
Версии ниже — наблюдения реестров на указанную дату. Наличие wheel подтверждает доступность сборки, но не успешную установку всего дерева зависимостей.

Проверенные места: [translator.py](../../src/geospoiler/ingestion/normalizer/translator.py), [CLI pipeline](../../src/geospoiler/cli/pipeline.py), [LLM backend](../../src/geospoiler/providers/llm_backend.py), [LightRAG ingest](../../src/geospoiler/retrieval/lightrag/ingest.py), [CLI query](../../src/geospoiler/cli/query.py), [smoke](../../src/geospoiler/operations/late_fusion_activation_smoke.py).
В backend уже есть ограничители, но sync и async используют отдельные семафоры: библиотека rate limiting сама по себе не обеспечит согласованный общий предел трёх вызовов.
В ingest уже есть helper переиспользования, однако обычный путь передаёт `reuse_processed=False`; здесь нужен корректный выбор и проверка существующего механизма, а не новая база задач.

## Карта возможностей по модулям

`Adopt` означает подходящую готовую возможность, `Extend` — небольшой адаптер к существующему модулю, `Build` — предметную логику своими средствами, `Later` — отложенный эксперимент, `Skip` — сейчас не добавлять.
Эти решения — рекомендации исследования, не разрешение на установку или изменение поведения.

| Модуль | Интересная возможность | Решение и граница |
| --- | --- | --- |
| `ingestion/fetcher` | Существующий Telethon и его RPC/FloodWait-механизмы | **Adopt existing**; сохранить sessions/checkpoints, реализовать согласованный выбор медиа. Новый Telegram framework не нужен. |
| `normalizer/translator` | Lingua: локальный язык с возможностью неопределённого результата | **Extend, первый пилот**; пропускать только уверенно русский, остальные оставлять существующему переводу. |
| `normalizer/web_handler` | Trafilatura перед браузерным Crawl4AI | **Extend, второй пилот**; article-first для подходящих страниц, браузерный fallback и исходный URL сохранить. |
| Документы/скриншоты | Docling с OCR и извлечением структуры | **Later/Extend**; отдельный маршрут для выбранных PDF, таблиц и документов, не для каждого Telegram-поста. |
| Нативные аудио/видео | faster-whisper | **Later**; локальная опция для уже выбранной транскрипции, только после сравнения русской/украинской речи. |
| YouTube ingestion | youtube-transcript-api | **Later**; возможный дополнительный способ получить timed captions, yt-dlp уже решает эту задачу. |
| `ingestion/enricher`, `contracts` | Pydantic и schema output уже используются | **Adopt existing**; Instructor/Guardrails сейчас добавят ещё один слой без установленной нужды. |
| Поток `normalize → enrich` | Стандартная bounded queue и единый координатор прогресса | **Build on stdlib**; не вводить Celery/Prefect ради одного локального конвейера. |
| `providers/llm_backend` | Общий предел синхронных и асинхронных обращений | **Extend existing**; конкурентность и запросы в секунду — разные ограничения. Готовый rate limiter не заменяет владение общим слотом и освобождение при отмене. |
| `retrieval/cards` | sqlite-vec как независимый dense baseline | **Later**; копия индекса и сравнение recall, действующие FTS/контекст не менять. |
| `retrieval/lightrag` | Существующие status/content reuse; maintenance-изменения upstream | **Extend existing**; сначала согласованная идемпотентность. Обновление 1.5.4 рассматривать отдельно на копии storage. |
| Embeddings/reranker | FlashRank; PyLate как более тяжёлый вариант | **Later**; сначала OFF-baseline и размеченные вопросы, reranker остаётся выключенным. |
| `answering` | Текущие Late Fusion, токенная упаковка и citations | **Keep**; не добавлять compression, новый verifier или другой synthesis framework. |
| `sources` | Существующий source registry + стабильные IDs для оценок | **Adopt existing**; сохранять происхождение, не вводить второй authoritative registry. |
| `wiki` | Graphiti как источник идей о временных фактах | **Later/Skip migration**; автоматическая память не заменяет approvals и immutable occurrences. |
| `ui` | Streamlit fragments и AppTest | **Adopt selectively**; возможности уже используемого framework, отдельный фронтенд не нужен. |
| `evaluation` | ir-measures; затем при необходимости Ragas | **Extend, третий пилот**; сначала оценки поиска по размеченным IDs без новых LLM-вызовов. |
| `operations`/CI | Полный offline pytest и blocking Ruff; Phoenix/Langfuse позже | **Existing tools first**; наблюдаемость не является текущей обязательной доработкой. |
| `cli` | Существующие команды и форматированные результаты | **Keep**; новый CLI framework не устраняет последовательность этапов или разрыв между `hybrid` и `mix`. |
| `testing_support` | Существующий `GEOSPOILER_NO_NETWORK` и изолированный offline runner | **Keep**; сохранить специальные проверки Windows/asyncio, не заменять работающий guard ради унификации. |
| `config`, `paths`, `compat` | Текущая конфигурация и разрешение старых логических адресов | **Keep**; сторонняя оболочка не должна менять identity root, source IDs или совместимые импорты. |
| Инструменты разработчика/MCP | Docling MCP для разовой проверки PDF | **Later**; полезный операторский инструмент при документном сценарии, не обязательная runtime-зависимость. |

Источники базовых возможностей: [Telethon RPC errors](https://docs.telethon.dev/en/stable/concepts/errors.html), [asyncio.Queue в Python 3.11](https://docs.python.org/3.11/library/asyncio-queue.html), [Pydantic models](https://docs.pydantic.dev/latest/concepts/models/).

## Кандидаты, которые стоит понять подробнее

### 1. Lingua — прямое попадание в задачу перевода

Lingua работает локально, различает русский и украинский и предоставляет confidence/relative-distance и результат `None` при неопределённости.
По её документации multilingual detection экспериментален, короткие фразы труднее; low-accuracy mode особенно ухудшает короткие тексты. Поэтому «получили ru» недостаточно для безопасного обхода перевода.
Пилот: вручную размеченные 50–100 реальных текстов ru/uk/en/смешанных, включая короткие подписи, цитаты, названия и отсутствие украинских специфичных букв. Измерять ошибочные пропуски перевода отдельно от количества сэкономленных вызовов.
Не ограничивать детектор только ru/uk, если в корпусе есть другие языки: относительная уверенность среди двух кандидатов не гарантирует русский язык входа.
**Решение: Extend после проверки.** При неопределённости оставлять действующий перевод; язык не должен менять текст или provenance.
Источник: [Lingua](https://github.com/pemistahl/lingua-py).

Совместимость: [PyPI 2.2.0](https://pypi.org/pypi/lingua-language-detector/2.2.0/json) требует Python `>=3.12`, имеет Windows CPython 3.14 wheel примерно 170 MB и не имеет обязательных runtime Python-зависимостей в metadata.
[Версия 2.1.1](https://pypi.org/pypi/lingua-language-detector/2.1.1/json) допускает Python `>=3.10`, но опубликованные Windows wheels покрывают 3.10–3.13, без 3.14.
Нельзя просто добавить latest и сохранить заявленную поддержку Python 3.11. Возможны условные версии с проверкой обеих веток или отдельная среда пилота; решение по поддержке Python здесь не принималось.

### 2. Trafilatura — извлекать статью без браузера, когда он не нужен

Сейчас `web_handler.py` создаёт `AsyncWebCrawler` для URL и берёт Markdown результата. Trafilatura предлагает извлечение основного текста/метаданных из HTML без обязательного браузера.
Это хороший кандидат на небольшой article-first маршрут: HTTP/HTML → extractor → проверка пригодности; Crawl4AI оставить для страниц, которым нужен рендеринг, и неудачного извлечения.
Пилот: 20–30 сохранённых страниц используемых сайтов, сравнение полноты статьи, чисел, цитат, таблиц и происхождения на одном HTML. Пустой результат нельзя считать успешным ускорением.
Нынешняя обрезка web-текста до 10 000 символов уже существует; исследование не предлагает сохранять её как новый критерий полноты или дополнительно сокращать источник.
**Решение: Extend после сравнения.** Browser fallback не устранит paywall или отсутствие доступа к источнику автоматически.
Источники: [проект и функции](https://github.com/adbar/trafilatura), [PyPI 2.3.1](https://pypi.org/pypi/trafilatura/2.3.1/json).

### 3. ir-measures — измерить, находит ли поиск нужные материалы

Библиотека считает стандартные retrieval-метрики по qrels и ranked runs: например Recall@k, reciprocal rank и nDCG.
Она подходит существующим стабильным `source_id`: можно сравнивать сохранённые выдачи без повторного synthesis и без LLM-судьи. Для сегментов нужен отдельный `segment_id` и соответствующая разметка.
Пилот: 30–50 настоящих вопросов, несколько допустимых источников на вопрос, градации релевантности и фиксированный корпус. Сравнить FTS, текущую fusion и одну конкретную альтернативу при одинаковом k.
Неполные qrels могут несправедливо считать новый хороший источник ошибкой; новые находки надо проверять. Метрики поиска не доказывают правильность готового ответа.
**Решение: Extend к текущему evaluation, наиболее лёгкая следующая ступень после ручной разметки.** Старые golden-оценки не являются новым benchmark нынешней Luna.
Источники: [документация](https://ir-measur.es/en/latest/), [код и Apache-2.0](https://github.com/terrierteam/ir_measures).

[ir-measures 0.4.3](https://pypi.org/pypi/ir-measures/0.4.3/json) требует Python `>=3.9` и `pytrec-eval-terrier>=0.5.5`.
У [pytrec-eval-terrier 0.5.11](https://pypi.org/pypi/pytrec-eval-terrier/0.5.11/json) есть Windows wheels для CPython 3.11 и 3.14; он требует NumPy/SciPy. Полное дерево не устанавливалось.

### 4. Docling — полезен для документов, а не как универсальная замена normalizer

Docling извлекает структуру документов, поддерживает PDF, таблицы, OCR и экспорт в структурированные форматы/Markdown. OCR-движок и языки выбираются отдельно.
Пилот: 10–15 действительно нужных PDF/скриншотов с русским/украинским текстом, таблицами и несколькими колонками. Проверять числа, порядок чтения и привязку к странице.
Результат должен войти в текущую цепочку normalized → Enriched v2 с provenance, а не создать параллельную базу документов.
**Решение: Later/Extend**, если такие материалы регулярно встречаются; для обычного Telegram-текста выгода не установлена.
Источники: [Docling](https://github.com/docling-project/docling), [OCR](https://docling-project.github.io/docling/concepts/OCR/), [PyPI 2.142.1](https://pypi.org/pypi/docling/2.142.1/json).

### 5. faster-whisper — возможная локальная транскрипция

Поддерживает CPU/GPU, квантование, timestamps и VAD через CTranslate2; это кандидат на опциональный backend для уже выбранной обработки речи.
Пилот: одинаковые 10 записей с русской/украинской речью, шумом и именами, сравнить смысловые ошибки, имена, числа, пропуски, время и память с текущим маршрутом.
Бенчмарки владельца нельзя переносить на этот Windows-хост как обещание ускорения. Для GPU нужны согласованные CUDA/cuDNN; для CPU скорость зависит от модели и оборудования.
**Решение: Later.** Сначала согласованная выборочность медиа, затем backend; замена не должна запускать анализ всех вложений.
Источники: [faster-whisper](https://github.com/SYSTRAN/faster-whisper), [PyPI 1.2.1](https://pypi.org/pypi/faster-whisper/1.2.1/json).

WhisperX интересен выравниванием и diarization, но [3.8.6 требует Python `<3.14`](https://pypi.org/pypi/whisperx/3.8.6/json), а также Torch/torchaudio/pyannote. В текущую среду его не рекомендовать; отдельные модели могут иметь собственные условия доступа.
У текущих CTranslate2, ONNX Runtime и PyAV найдены Windows-сборки, подходящие 3.14; успешная установка и качество faster-whisper здесь не проверены.

### 6. sqlite-vec — дешёвый независимый dense baseline

Расширение хранит и ищет векторы прямо в SQLite, без отдельного сервера; есть Windows wheel. Это соответствует локальному устройству проекта лучше новой серверной БД.
Полезный вопрос эксперимента: «что даёт простой dense канал рядом с FTS относительно текущего LightRAG?» Это не готовый довод выбросить граф.
Пилот: отдельный индекс на копии карточек, существующие embeddings с проверенной идентичностью/размерностью либо явный отдельный эксперимент; сравнить recall и latency по размеченным вопросам.
Нельзя смешивать в одном пространстве векторы разных моделей; перенос потребует собственной схемы актуальности и проверки индекса.
**Решение: Later.** Проект pre-v1 предупреждает о breaking changes; обычный пользовательский query не переключать автоматически.
Источники: [sqlite-vec](https://github.com/asg017/sqlite-vec), [PyPI 0.1.9](https://pypi.org/pypi/sqlite-vec/0.1.9/json).

### 7. FlashRank и PyLate — проверять после появления задачи ранжирования

FlashRank предлагает CPU/ONNX reranking без Torch для pairwise-варианта. Его маленькая модель по умолчанию не является доказанно подходящим выбором для русского корпуса; есть multilingual-модель около 150 MB.
Пилот: сохранённый одинаковый пул кандидатов, OFF против одного multilingual reranker, слепая оценка source relevance. Не сокращать согласованное содержание контекста как скрытую часть эксперимента.
**Решение: Later**, если текущие выдачи дают конкурирующие близкие материалы и разметка показывает проблему порядка.
Источники: [FlashRank](https://github.com/PrithivirajDamodaran/FlashRank), [PyPI 0.2.10](https://pypi.org/pypi/flashrank/0.2.10/json).

PyLate интересен ColBERT/late interaction: более подробное сопоставление токенов запроса и документа. Но это отдельные модели и многовекторный индекс, не маленькая настройка текущего Qwen embedding.
**Решение: Later, ниже FlashRank по простоте пилота.** Библиотека требует Sentence Transformers/Transformers, datasets и FastPLAID; Windows/3.14 цепочка не проверена. Лицензия модели проверяется отдельно от MIT библиотеки.
Источники: [PyLate](https://github.com/lightonai/pylate), [PyPI 1.6.0](https://pypi.org/pypi/pylate/1.6.0/json).

### 8. Ragas, DeepEval и Promptfoo — только если своего harness становится мало

Ragas даёт готовые определения метрик retrieval/answer evaluation, включая варианты context precision по IDs и без LLM. Разумно сначала заимствовать понятия и формат данных, затем решать, нужен ли весь пакет.
**Решение: Later/Extend для offline-экспериментов**, после ir-measures. Judge-метрики создают расходы и ошибки судьи; нужен отдельный проверенный адаптер Luna, не подмена backend или модели.
Источники: [Ragas context precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/), [Ragas](https://github.com/vibrantlabsai/ragas), [PyPI 0.4.3](https://pypi.org/pypi/ragas/0.4.3/json).
DeepEval — ещё одна полноценная eval-платформа с pytest-подходом; одновременно с Ragas не добавлять. **Skip сейчас**: существующий harness уже есть, выбранного пробела, требующего второй платформы, не установлено. [Код](https://github.com/confident-ai/deepeval), [PyPI 4.3.1](https://pypi.org/pypi/deepeval/4.3.1/json).
Promptfoo удобен для табличного сравнения и Python custom provider; **Later**, если понадобится интерфейс экспериментов. npm 0.125.1 требует Node `>=22.22.0`, имеет 76 прямых dependencies и вводит второй runtime. [Python provider](https://www.promptfoo.dev/docs/providers/python/), [npm metadata](https://registry.npmjs.org/promptfoo/0.125.1).

### 9. Небольшие возможности для UI, Wiki и разработчика

Streamlit `st.fragment` позволяет обновлять часть интерфейса, а `AppTest` проверять отображаемые элементы без отдельного browser harness. **Adopt selectively** при конкретной UI-задаче; не оборачивать весь Reviewer без причины.
Пилот: один элемент очереди — изменение/сохранение/переход к следующему; проверить, что повторное выполнение не дублирует запись и выключенная Wiki не появляется. [Fragments](https://docs.streamlit.io/develop/api-reference/execution-flow/st.fragment), [AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest).
Graphiti моделирует временную историю и изменение фактов. **Later** как идеи для вопросов «что считали верным на дату», но его автоматическая invalidation не соответствует автоматически политике approvals и неизменяемых claim occurrences GeoSpoiler. [Graphiti](https://github.com/getzep/graphiti).
RapidFuzz может помогать предлагать похожие написания для ручной проверки. **Later**, только при конкретном списке опечаток; строковая близость не означает тождество сущностей, автоматический merge запрещён предметной моделью. [RapidFuzz](https://github.com/rapidfuzz/RapidFuzz).
Официальный Docling MCP даёт conversion-инструменты и кеш документов. **Later** для разового исследования выбранного PDF; библиотечный вызов проще для обычного ingestion. Подключение глобальных MCP-настроек не выполнялось. [Docling MCP](https://github.com/docling-project/docling-mcp).

## Предлагаемый порядок

1. Выполнить существующий ingestion-план и рабочие проверки `run`/`load`; не начинать со смены RAG-движка.
2. Внутри задачи перевода провести маленький Lingua-пилот и решить совместимость Python 3.11/3.14.
3. На востребованных web-источниках проверить Trafilatura перед Crawl4AI, сохраняя полноту и происхождение.
4. Разметить вопросы и источники; добавить ir-measures к сохранённым выдачам, если готового отчёта недостаточно.
5. Docling, локальный ASR, dense baseline и reranking рассматривать отдельными экспериментами по конкретной потребности.

Критерий принятия каждого кандидата: он решает наблюдаемую задачу, сохраняет согласованный контракт, даёт измеряемый полезный результат и оправдывает сопровождение своих зависимостей.
В ходе этого исследования изменён только этот новый отчёт. Код, модели, индексы, конфигурация, исходные материалы и внешние настройки не менялись.
