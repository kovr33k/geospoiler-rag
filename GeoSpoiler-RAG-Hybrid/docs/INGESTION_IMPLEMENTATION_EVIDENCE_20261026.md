## Реализовано

Задачи №4–9 объединены в одной ветке: локальный пропуск перевода уверенно русского текста, общий предел трёх LLM-вызовов, немедленная передача готовых материалов через ограниченную очередь, выборочная обработка вложений, переиспользование валидных карточек при смене модельных настроек и инкрементальный явный `load` с `--force`.

Локальный детектор Lingua сравнивает русский с украинским и болгарским по отдельным фрагментам; смешанный, иностранный и неопределённый текст сохраняет перевод. PDF с текстовым слоем извлекается локально через pypdf; скан без текста получает диагностический статус. Обе зависимости объявлены в пакетных спецификациях и включены в release environment identity. Обработка медиа по подписи может пропустить важное вложение — технические тесты не измеряют качество этих правил на реальных пересылках.

Принятое пользователем упрощение Ponytail применено: публикация использует существующие атомарные helpers. Перезапись старой пары дополнительно защищена существующим журналом восстановления, включая legacy sidecar без текстового файла. Координатор резервирует YouTube identity до запуска worker; dedicated-источник имеет приоритет над прежним fallback. Checkpoint продвигается по успешному префиксу с линейным числом операций.

Текущие `gpt-6-luna`, профиль `luna` и `xhigh` сохранены. Код сборки контекста и правил ответа не изменялся. `run` не выполняет загрузку графа. Рабочие базы и исходный dirty checkout не использовались для приёмки.

- Сквозные проверки вызывают реальные `run` и `load`, запись карточек, FTS и source registry в изолированных каталогах. Управляются внешние ответы Telegram/LLM/LightRAG и границы преобразования видео; реальный PDF fixture проходит извлечение текста.
- В полном первом прогоне обнаружены и устранены зависимости release-проверок от прежней `origin/master` и smoke fixture от локального `.env`. Доверенная release-база теперь `origin/main`; произвольная база по-прежнему запрещена. CI получает историю для вычисления merge-base.
