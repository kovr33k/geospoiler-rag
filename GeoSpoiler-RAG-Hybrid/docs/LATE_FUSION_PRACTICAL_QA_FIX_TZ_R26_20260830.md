# ТЗ: исправления по практическому QA Late Fusion R26

Дата: 2026-08-30  
Статус: **выполнено и принято 2026-08-30**

## 1. Контекст проверки

После завершения R25 запущен штатный live smoke из 10 разноплановых вопросов:

`python scripts/late_fusion_activation_smoke.py --output artifacts/manual_qa_smoke_20260830.json`

Активная конфигурация: Luna, `LATE_FUSION_ENABLED=true`,
`RERANKER_ENABLED=false`, `WIKI_ENABLED=false`. Загружены существующие граф,
Enriched-карточки, Card FTS и YouTube FTS.

Первый результат: **9/10** вопросов прошли автоматический контракт. Все десять
ответов дополнительно прочитаны вручную. Девять ответов содержательно корректны:
они отвечают по найденным материалам, не выдумывают отсутствующие сведения и
отделяют факты от заявлений, прогнозов и обвинений.

Проблемный `SMOKE_MEDIA` на первом запуске переключился в
`legacy_fallback`, вернул найденные названия файлов без URL и без `[S#]`:

- `pipeline_not_late_fusion`;
- `citations_empty`;
- `invalid_reference_url`.

Точечный повтор того же вопроса без изменения данных прошёл через Late Fusion:
вернул 13 цитированных материалов и валидные Telegram/YouTube URL. Следовательно,
карточки, граф, SQLite-индексы и source registry не потеряны; ошибка
нестабильна и относится к query-time synthesis/fallback.

## 2. Найденные проблемы

### P1 — единичная ошибка synthesis превращает корректный source-запрос в бесполезный legacy fallback

Первый `SMOKE_MEDIA` нашёл содержание нужных карточек, но конечный ответ сообщил,
что URL отсутствуют, хотя при повторе те же URL корректно восстановились. Для
пользователя это ложный отрицательный результат.

Точная первичная причина не записана в smoke-артефакт: отчёт сохраняет только
`pipeline=legacy_fallback`, но отбрасывает `late_fusion.fallback_reason`.
По имеющимся данным нельзя честно выбрать между `missing_citation`,
`unknown_citation`, `invented_url`, ошибкой Luna или другим разрешённым поводом
для fallback.

Требуется:

1. Сохранять безопасный `fallback_reason` в каждом case штатного smoke и в
   диагностике пользовательского запроса.
2. Для исправимых нарушений финального citation-контракта выполнять не более
   одного повторного synthesis на том же immutable наборе источников с более
   строгим требованием использовать только переданные `[S#]` и URL.
3. Не повторять retrieval, не менять ранжирование и не добавлять новые данные
   между попытками.
4. Если повтор не прошёл, source-запрос не должен превращать существующие
   canonical HTTP(S) URL в пустые `card-1`, `1`, `2` references. Нужно либо
   вернуть безопасный ответ с уже гидратированными canonical references, либо
   явно сообщить о невозможности сформировать проверяемый ответ.
5. Добавить regression-тесты для каждого retryable citation failure и для
   окончательного отказа после одной повторной попытки.

### P2 — текстовые таймкоды YouTube не всегда соответствуют кликабельным ссылкам

В `SMOKE_YOUTUBE` ответ содержательно разобрал интервалы `00:00:03–06:04`,
`06:04–11:53` и `11:53–16:59`, но основная цитата `[S1]` содержала только один
`start_url` с началом около 3 секунд. Автоматический smoke проверяет лишь наличие
хотя бы одного `start_url`, поэтому не замечает, что остальные заявленные
интервалы не имеют своих проверяемых якорей.

Требуется:

1. Сохранять отдельный reference/start URL для каждого фактически использованного
   YouTube-сегмента либо эквивалентную однозначную привязку таймкода к ссылке.
2. Если в ответе указан новый временной интервал, рядом должна быть цитата,
   ведущая к началу соответствующего сегмента.
3. Добавить тест с тремя сегментами одного видео: три различающихся таймкода в
   ответе должны разрешаться в три корректных `start_url`.
4. Усилить `SMOKE_YOUTUBE`: проверять соответствие заявленных таймкодов ссылкам,
   а не только `youtube_start_url_count > 0`.

## 3. Критерии приёмки

1. `SMOKE_MEDIA` стабильно проходит через `pipeline=late_fusion`, содержит
   `[S#]` и только валидные HTTP(S) references.
2. При искусственных `missing_citation`, `unknown_citation`, `invented_url` и
   empty/corrupt synthesis выполняется максимум одна ограниченная повторная
   попытка; причина и исход наблюдаемы.
3. При окончательном fallback canonical URL найденных источников не заменяются
   пустыми ссылками.
4. Smoke-артефакт содержит `fallback_reason` для каждого case, где pipeline не
   равен `late_fusion`.
5. YouTube-ответ с несколькими временными интервалами содержит проверяемые
   segment-level ссылки для каждого использованного интервала.
6. Проходят профильные unit/regression-тесты и один чистый официальный smoke
   10/10. Полный повтор enrichment всех карточек не требуется: проблема находится
   в query-time обработке уже корректно опубликованных данных.

## 4. Не входит в ТЗ

- повторное обогащение 131 карточки;
- пересборка графа без изменения его входных данных;
- Wiki, reranker, security/release-evidence hardening;
- изменение содержательных данных карточек.

## 5. Выполненная реализация и приёмка

В `loader/late_fusion.py` добавлена одна ограниченная повторная попытка только
для исправимых ошибок финального ответа: `missing_citation`,
`unknown_citation`, `invented_url` и empty/corrupt output. Retrieval, порядок и
набор источников между попытками не меняются. В trace сохраняются обе попытки и
`synthesis_retry_count`.

Если повторный source-ответ тоже не проходит контракт, `loader/query.py` больше
не заменяет найденные canonical URL пустыми legacy references. Пользователь
получает безопасный детерминированный список уже гидратированных источников, а
trace сохраняет точный `fallback_reason`.

Для YouTube каждый выбранный сегмент теперь присутствует в reference как
`segment_start_urls`. Упомянутые таймкоды детерминированно превращаются в ссылки
на соответствующую секунду. Обработаны диапазоны, уже обёрнутые моделью в одну
Markdown-ссылку: они разбиваются без вложенных ссылок. Дробные `start_seconds`
приводятся к секунде тем же округлением вниз, которое используется в `&t=...s`.

В `scripts/late_fusion_activation_smoke.py` сохраняется `fallback_reason`,
segment-level metadata и проверяется, что несколько названных YouTube-сегментов
имеют соответствующие URL в ответе.

Фактическая проверка:

- targeted Late Fusion/release tests: **89 passed**, затем новые R26-тесты:
  **28 passed, 2 subtests passed**;
- Ruff и compileall: успешно;
- финальный общий suite: **1151 passed, 4 skipped, 44 subtests passed**,
  только 2 сторонних deprecation warnings;
- официальный live smoke:
  `artifacts/manual_qa_smoke_r26_final_20260830.json` — **10/10 passed**;
- `SMOKE_MEDIA`: `pipeline=late_fusion`, 20 references, 16 citations, errors=[];
- `SMOKE_YOUTUBE`: `pipeline=late_fusion`, три segment timestamp URL присутствуют
  в ответе, вложенных Markdown-ссылок нет, errors=[].

Карточки, граф, FTS, source registry и SQLite не перестраивались: исправление
касается только query-time формирования, проверки и резервной выдачи ответа.
